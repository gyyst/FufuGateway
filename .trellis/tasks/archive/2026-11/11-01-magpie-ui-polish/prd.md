# 参考 Magpie 优化管理台交互与视觉体验（批次 1：基础体验）

## Goal

参考 Magpie「集中配置、一屏洞察、可搜索选择」的交互理念，提升 FufuGateway 管理台在信息架构、选择器、空状态、仪表盘和主题上的体验。保持零构建、零新依赖，不修改任何后端接口。

本任务承接已完成的 `10-31-magpie-feature-parity`（Provider 预设、快速开始、路由诊断、网关自测、客户端接入）。本轮不重复其后端能力建设，只优化管理台交互层。

## Background

实测本地管理台（2026-11-01）发现：

- 概览页使用 `Promise.all`，任一接口失败即整页「加载失败 · Configuration validation failed with 3 error(s)」，空配置实例无法使用。
- 14 个页面在侧边栏平坦排列，缺少分组；`980px` 断点下侧边栏塌陷为三列链接，导航失去层级。
- 模型/目标选择全部使用原生 `select`，模型数量增长后不可搜索，与 Magpie 的核心交互差距最大。
- 路由诊断与请求详情仅输出 JSON，无可读的路由决策视图（留待批次 2）。
- 列表空状态仅显示「暂无数据」，无下一步操作引导；表格无搜索、排序、分页。
- Provider 表格存在徽章与操作按钮换行、列宽失衡等排版问题。
- 仅暗色主题；用量页筛选控件堆叠为整行按钮，趋势仅为横向条形。

## Users and Scenarios

### 场景 A：首次部署（空实例）

管理员登录后进入概览：即使配置校验失败或接口部分异常，也能看到可理解的降级卡片与「去快速开始」引导，而不是整页错误。

### 场景 B：模型数量较多

管理员在路由诊断、Combo 节点、别名/通配符目标、API Key 白名单、用量筛选中，通过输入关键字快速定位 `provider/model`，键盘可完成选择。

### 场景 C：日常巡检

管理员在概览一屏看到健康状态、配置版本与未发布变更、近 30 天请求与费用、错误率、熔断数量，并能直接进入待处理项。

### 场景 D：列表管理

管理员在 Provider/模型/Combo 等列表页通过搜索、排序、分页快速定位记录；空列表时看到带操作按钮的引导。

### 场景 E：偏好

管理员在顶栏切换亮/暗主题，刷新后保持选择。

## Requirements

### R1. 导航信息架构与响应式

- 侧边栏按分组展示：概览 / 接入（Provider、模型、别名、通配符、Combo）/ 访问（用户、API Key）/ 观测（用量与请求、路由诊断）/ 设置（客户端接入、配置与审计）；「快速开始」独立置顶。
- 分组标题可辨识，当前页高亮，分组不影响既有 hash 路由（`#/page`）。
- `<= 980px` 时侧边栏改为抽屉式：顶栏汉堡按钮打开/关闭，带遮罩与 `Esc` 关闭，不出现三列散乱链接。

### R2. 全局状态栏

- 顶栏在页面标题右侧展示：连接状态、生效配置版本（未发布时显示「未发布」）、待发布变更标记、非 CLOSED 断路器数量。
- 状态数据来自现有 `/admin/health` 与 `/admin/config/current`，失败时静默降级为「状态不可用」，不阻塞页面。
- 状态在登录后加载，并在路由切换时按需刷新（缓存不超过 30 秒）。

### R3. 可搜索模型选择器

- 新增零依赖 combobox 组件：输入即过滤、按 Provider 分组、展示条目描述、支持上下键/回车/Esc、点击外部关闭、`aria-expanded`/`aria-activedescendant`。
- 替换以下场景的原生下拉：路由诊断模型、Combo 节点目标、别名/通配符路由目标、API Key 模型白名单/权限模型、用量页模型筛选。
- 单选与多选（带已选项标签）两种模式；表单提交值与原 `select`/checkbox 方案保持一致，不改变后端请求体。
- 无可选项时展示与当前空状态一致的引导文案。
- 保留键盘可访问性与移动端可用性。

### R4. 概览页仪表盘重构

- 使用 `Promise.allSettled`，任一接口失败只影响对应卡片；整页不再因单个 400/500 崩溃。
- 指标卡：数据库状态、生效配置版本与待发布状态、近 30 天请求数、近 30 天费用、错误率（基于现有请求数据）、非 CLOSED 断路器数。
- 增加纯 SVG 迷你趋势图（请求量/费用），无第三方依赖。
- 增加 Top 模型或 Provider 摘要（基于现有 summary/requests 数据；数据不足时隐藏而非报错）。
- 空配置或未初始化时，展示「去快速开始」引导与未完成项，而非错误文本。

### R5. 列表空状态与表格增强

- 通用表格支持：关键字搜索（前端过滤）、点击表头排序、分页（前端分页，默认 20 条/页）。
- 各列表页空状态提供下一步操作：Provider（从预设添加/新建）、模型（同步或新建）、Combo（新建）、API Key（创建）、用量（暂无请求时说明如何产生第一条请求）。
- 修复 Provider 表格徽章、账户数、操作按钮换行与列宽问题。
- 不改变现有 API 分页/筛选语义；搜索排序分页均在前端完成。

### R6. 亮/暗主题

- 增加亮色主题，保留现有深色为默认。
- 顶栏提供切换按钮；选择持久化到 `localStorage`，刷新后保持。
- 首次渲染避免明显闪烁（通过同源同步初始化脚本或等价方案，且不违反 CSP）。
- 两个主题下所有页面、表格、徽章、表单、弹窗、图表对比度可读。

## Non-Goals

- 不修改任何后端 API、数据库表、配置发布流程。
- 路由诊断执行树可视化、请求详情链路视图（批次 2）。
- 用量页深度图表、缓存命中/推理 Token 细分、Provider 分布（批次 2）。
- 客户端接入向导按代理生成配置（批次 2）。
- Ctrl+K 命令面板、Provider 健康卡片视图、配置快照命名与对比（批次 3）。
- 菜单栏/TUI/CLI、代理配置改写、订阅账号复用、隐私掩码、Web 搜索/图片工具（与 Cloudflare Workers 网关定位不符）。
- 不引入前端框架、构建工具或运行时依赖。

## Constraints

- 兼容 Cloudflare Workers Static Assets 与现有 CSP（`script-src 'self'`，禁止内联脚本）。
- 保持零构建；若使用 ES modules，必须同源并可被现有静态资源服务直接提供。
- 不新增依赖（`package.json` 不变）。
- 不破坏现有 14 个页面、登录、CRUD、发布/回滚、诊断与自测流程。
- 所有新增文本与注释使用中文，与现有管理台一致。
- 颜色/间距沿用现有 CSS 变量体系，不另起设计系统。

## Acceptance Criteria

- [ ] 空配置实例打开概览页，不显示整页「加载失败」；至少显示降级卡片和快速开始引导。
- [ ] 侧边栏显示五个分组与置顶的快速开始；`980px` 以下为抽屉导航，汉堡按钮与遮罩可用。
- [ ] 顶栏展示连接状态、配置版本/未发布、断路器数量；接口失败时不阻塞页面。
- [ ] 路由诊断、Combo 节点、别名/通配符目标、API Key 白名单、用量筛选均使用可搜索 combobox，键盘可选，提交值与原实现一致。
- [ ] Provider/模型/Combo/API Key 列表支持搜索、排序、分页；空列表有可点击的下一步操作。
- [ ] 概览页包含迷你趋势图、错误率与 Top 模型/Provider 摘要（无数据时隐藏）。
- [ ] Provider 表格无徽章/按钮异常换行。
- [ ] 亮/暗主题切换可用并持久化，两主题下页面可读。
- [ ] `npm run typecheck`、`npm test`、`npm run deploy:dry-run` 通过。
- [ ] Playwright 手工走查：登录、各页面渲染、空状态、combobox、主题切换、抽屉导航。
- [ ] 工作区不残留临时文件；`package.json` 无变化。
